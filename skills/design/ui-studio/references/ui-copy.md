# UI copy rules (merged)

Moved here from SKILL.md "Core rules and checklists" to keep SKILL.md under its
line cap. Apply it in step 4.2 (copy before layout), in UI copy mode and in the
step 6.2 copy self-audit. Sources: content-design, typography, v2, taste-skill, impeccable clarify.

- Sentence case for titles, labels, menus and buttons; contractions; US English; the Oxford comma; no
  Latin abbreviations (e.g., i.e., etc., via, vs).
- Per state, decide the one fact the user needs now, the next action, the context that changes the
  decision, and the tone for the moment; say each idea once [impeccable clarify].
- A single fragment takes no period; when a group has several sentences, every one takes a period.
- Buttons: a verb plus an object, at most 3 words, never wrapping at desktop. Destructive actions name the
  thing ("Delete workflow"). "Cancel" aborts a process, "Close" dismisses information. One label per
  intent across the page.
- Errors: what happened, why if known, what to do next; never blame the user ("The API key isn't valid").
- Empty states explain the area and give the next step. Placeholders show a realistic example, never the
  label again. Tooltips add what the label cannot, in one or two sentences.
- Loading: "Loading orders…" (real ellipsis, no period). Success: past tense, no exclamation ("Order
  saved"). Status labels in sentence case ("Active", "Error").
- Truncate names at the end, paths in the middle, full text on hover or focus. One "please" per surface at most.
- Sourced components (Watermelon, Skiper UI) arrive with demo strings, author emails and links: every
  one is rewritten or removed by these rules before the item counts as installed (`component-sources.md`).
